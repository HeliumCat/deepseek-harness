# Subagent 创建与管理规范

本规范面向调用 DeepSeek Harness Pet MCP 的 Agent。调用方负责规划、任务拆解、授权、结果整合和最终验收。Pet 的 lead subagent 按请求创建执行子代理并回传结果。执行子代理在给定范围内完成明确任务。

## 1. 核心原则

- 只将输入、输出、范围和验收标准明确的任务交给执行子代理。
- 授予完成当前任务所需的最小权限。涉及文件创建、修改或代码执行时，使用经过验证的隔离工作区。
- 独立检查实际产物和执行证据。是否接受、采用或发布，由调用方决定。

## 2. 适用场景

适合委派的任务可以独立执行，输入已明确，操作步骤可约束，输出可独立检查，并能用具体标准验收。典型任务包括按规则批量处理文件、从指定来源提取数据、按给定方案修改代码、生成指定格式的文件、执行指定命令、检查格式或语法，以及对相互独立的数据项重复同一流程。

用户要求监督正在运行的任务时，如果状态可从子代理能访问的来源独立判断，优先委派只读观察。给出运行 ID 或日志位置、检查间隔、最长等待时间，以及完成、失败、超时的判据。要求子代理在触发停止条件时报告时间、状态、证据和最后一次进度。调用方负责决定是否继续、重试或介入。

对于需要实时协调、频繁决策，或输入、输出和执行范围仍有歧义的任务，调用方应先补齐信息或细化任务。

## 3. 任务边界

调用方承担复杂判断、技术选型、架构设计、执行策略和最终决策。执行子代理可以按给定规则分类日志、做统计或提取信息。委派前检查任务是否能在既定方案和范围内完成，是否无需引入新的复杂决策。

## 4. 创建请求

每次调用 `subagent_delegate` 提供一个执行单元。复用同一调用方会话的 `agentSession`。

需要到点执行时，调用 `subagent_schedule` 并提供同一组任务字段，再指定 `runAt` 或 `delaySeconds`。它立即返回派发 ID 和计划时间。执行结果保存在 Pet 历史中。

用户要求 Pet 周期执行一个任务时，给 `subagent_schedule` 传 `everySeconds`，例如 `300` 表示每 5 分钟执行一次。保存后向用户报告计划 ID 和首次运行时间。需要查询最近结果、暂停、恢复或停止未来的执行时，使用 `subagent_schedule_manage`。每次执行都有独立的派发记录，可以在 Pet 历史按计划 ID 查找。

用户给出持续时间时传 `durationSeconds`，给出执行次数上限时传 `maxRuns`。例如「每分钟执行一次，持续一小时」使用 `everySeconds: 60` 和 `durationSeconds: 3600`。Pet 到达条件后停止安排新一轮，已派发的任务可以完成。

- 在 `task` 中写明目标和边界，列出精确的输入、执行步骤、允许访问的资源及禁止的操作。
- 在 `acceptanceCriteria` 中逐项写明调用方将检查什么、用什么方法检查、预期结果和所需证据。交付物可做单元测试时，写明调用方将编写并运行的测试用例及其预期结果。
- 在 `expectedReturn` 中指定报告格式、所需文件和必须返回的状态。
- 选择模型或推理强度时通过 `list_subagent_models` 查询可用值。使用 `maxDepth` 和 `maxSubagents` 限制递归。

子代理执行期间，调用方不得并行执行已经委派的同一项工作，也不得重复制作同一交付物。调用方可以推进其他独立工作或等待结果。收到结果后，再按第 8 节独立验收。

## 5. 停止条件

缺少必要输入、有歧义、权限不足、操作失败，或继续执行可能造成不可逆影响时，执行子代理停止相关操作，报告已完成工作、阻塞原因和需要调用方决定的事项。保持原始输入、方案和任务范围。范围外的问题可以报告。执行报告必须如实记录实际操作和测试结果。

## 6. 最小权限

只提供任务所需的工具、输入文件和工作目录。保护无关项目目录、其他子代理的工作区、网络、外部服务、凭证、密钥和环境变量。授权前评估权限用途、影响、能否缩小范围和有无安全的执行方式。

当前 Pet 的执行子代理使用配置中的 DSH 预设，默认是 `standard`。调用方应按实际生效的部署配置判断权限。任务文字能描述执行约束。需要按次授予文件、网络或命令权限时，只有已经提供相应运行时控制的环境才适合执行。

## 7. 临时工作空间

执行代码、修改文件或生成产物时，为每个执行子代理分配独立的临时工作区，仅提供所需输入。将写入、编译产物、缓存和临时文件限制在该工作区，按需要划分输入、工作、输出和日志目录。访问工作区外资源、覆盖或删除已有文件、将文件同步到持久位置都需要明确授权。

独立目录是工作位置。安全隔离需要实际的文件系统、进程和工具访问控制。调用方在派发前确认后端具备所需限制。

## 8. 独立验收

把执行子代理的报告和自测结果当作待验证的信息。调用方应检查实际交付物，按派发时给出的 `acceptanceCriteria` 逐项使用约定的方法验收。交付物可做单元测试时，由调用方编写并运行约定的单元测试，记录实际结果。

验收时不得重做已经委派的同一项工作。根据验收标准，用约定的样本和断言检验交付物，或核对实际执行记录。检查是否有超范围修改或其他副作用，记录无法验证的项目。如报告与实际检查冲突，依据检查结果调查原因。

## 9. 交付与清理

要求执行子代理返回任务状态、摘要、产物清单和位置、关键操作、实际运行的测试及结果、遗留问题和待确认事项。调用方验收后决定是否采用、迁移、发布、保留或清理。保留待验收的产物，直至调用方确认处置方式。

## 10. 执行顺序

先判断是否适合委派，再写明任务和验收标准，确认权限与隔离后创建子代理。任务较大时，由调用方拆成可独立检查的执行单元。执行结束后，由调用方验证、整合结果并安排资源清理。
